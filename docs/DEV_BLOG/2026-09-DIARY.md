## 2026-09-28: iOS build needs DXVK's nested header submodules

A fresh iOS build stopped in the DXVK meson configure step with
`ERROR: Problem encountered: Missing Vulkan-Headers`. The README's
iOS quick start ran `git submodule update --init references/fbraz3-dxvk`
without `--recursive`, so the fork's own `include/vulkan` and
`include/spirv` submodules were never checked out. The macOS build can
fall back to the Vulkan SDK headers, but the iOS cross build uses the
iPhoneOS sysroot and has no such fallback.

- `README.md`: the iOS quick start now uses `--recursive`.
- `cmake/dx8.cmake`: the iOS configure fails early with the exact fix
  command when those headers are missing, instead of failing deep in
  the ninja build.
